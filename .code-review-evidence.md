# Code Review Evidence — Configurable init timeout

**Date:** 2026-03-02
**Change:** Make LSP server initialization timeout configurable per server
**Files:** config.ts, client.ts, lsp-config.json
**Blast Radius:** Low — 3 files, additive config field, no API surface change

## Summary

Pyright (Python language server) exceeds the hardcoded 45s initialization timeout on larger workspaces, causing Python tools to hang. Made the timeout configurable via `initTimeout` in lsp-config.json, defaulting to 45s for backward compatibility. Set Python to 120s.

## Changes

1. **config.ts** — Added `initTimeout: z.number().int().positive().optional()` to `LspServerConfigSchema`
2. **client.ts** — Renamed `INIT_TIMEOUT_MS` to `DEFAULT_INIT_TIMEOUT_MS`, added `initTimeoutMs` instance field that reads from `config.initTimeout ?? DEFAULT_INIT_TIMEOUT_MS`
3. **lsp-config.json** — Added `"initTimeout": 120000` to Python server entry

## Security Review

- No new dependencies or imports
- No user input reaches the timeout value (config file only)
- Positive integer validation via Zod schema
- No secrets, credentials, or PII

## Correctness Review

- Default 45s preserved for servers without `initTimeout` (backward compatible)
- Zod `.optional()` means field can be omitted (existing configs still parse)
- `.strict()` on schema already present — no risk of extra fields leaking
- 84/84 tests pass, typecheck clean, build clean

## Verdict

APPROVE — Minimal, backward-compatible fix for a confirmed initialization timeout.
