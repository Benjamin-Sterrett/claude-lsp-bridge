# Implementation Plan — PR2: LSP Client + Manager

## Problem
We need the core LSP client layer that spawns language server subprocesses, performs the LSP 3.17 initialization handshake, syncs file content (didOpen/didChange/didClose), caches diagnostics, and handles crash recovery. We also need a manager that routes requests to the correct client by file extension.

## Approach
Two new files in `src/lsp/`:
- `client.ts` — LspClient class wrapping a single language server subprocess
- `manager.ts` — LspManager routing by file extension, lazy initialization

Using `vscode-jsonrpc` for the JSON-RPC transport (createMessageConnection + StreamMessageReader/Writer) and `vscode-languageserver-protocol` for LSP types and method constants.

## Key Design Decisions
1. **createMessageConnection** from `vscode-jsonrpc/node` — spawn child process, pipe stdio
2. **LSP 3.17 init** — send `initialize` with `capabilities.general.positionEncodings: ['utf-8', 'utf-16']`, read server response to determine negotiated encoding
3. **Full-text sync** — `textDocumentSync: Full` (simpler, sufficient for v1). Re-read file from disk before each query, send didOpen on first access or didChange if content differs
4. **Diagnostics cache** — listen on `textDocument/publishDiagnostics` notification, cache per URI with version
5. **Crash recovery** — detect subprocess exit, single auto-restart with 2s backoff
6. **Graceful shutdown** — send `shutdown` request then `exit` notification per LSP spec
