# Implementation Plan — PR4: MCP Server Wiring

## Problem
We have 6 tool handlers, an LspManager, and config loading — but no entry point. This PR creates `src/index.ts`, the MCP server binary that registers all 6 tools with `@modelcontextprotocol/sdk`, routes calls to the tool handlers, and handles graceful shutdown. After this PR, the server can be registered with Claude Code via `claude mcp add`.

## Approach
Use the `McpServer` high-level API from `@modelcontextprotocol/sdk/server/mcp.js` with `StdioServerTransport`. This gives us:
- `server.registerTool(name, { description, inputSchema }, callback)` for each of the 6 tools
- Automatic ListTools/CallTool request handling
- `server.connect(transport)` for stdio communication

Each tool callback will:
1. Receive validated arguments (SDK validates against inputSchema zod schema)
2. Call the existing tool handler function (e.g., `findDefinition(manager, params)`)
3. Return the `ToolResult` (which already matches MCP's `{ content: [...] }` format)
4. Catch errors and return `{ content: [{ type: 'text', text: error.message }], isError: true }`

Graceful shutdown via idempotent `shutdown()` function wired to:
- `process.on('SIGINT'/'SIGTERM')`
- Transport/stdin close events (MCP parent process disconnect)

Integration test: spawn the MCP server as a child process, use MCP Client SDK to call tools/list and tools/call, verify responses.

## Existing Patterns to Reuse
- `loadConfig()` from `config.ts` — already handles env var, local file, default file, auto-detect
- `LspManager` from `lsp/manager.ts` — already manages client lifecycle
- All 6 tool handlers return `ToolResult` compatible with MCP `CallToolResult`
- `toolError()` from `types.ts` — existing error formatting

## Key Design Decisions
1. **McpServer (high-level API)** — not raw `Server` class. `registerTool()` handles schema validation, ListTools, and CallTool routing automatically.
2. **Zod input schemas as single validation source** — `registerTool` validates args via zod; callbacks just forward to handlers. No duplicate validation.
3. **Error boundary per tool** — each tool callback wraps the handler in try/catch, returning `isError: true` on failure. This prevents one bad tool call from crashing the server.
4. **Config loading at startup** — `loadConfig()` called once in `main()`. Failure = log to stderr + exit(1).
5. **No stdout logging** — all logging goes to stderr (stdout is reserved for MCP JSON-RPC).
6. **Idempotent shutdown** — single `shutdown()` function guards against double-shutdown via flag. Wired to SIGINT, SIGTERM, and transport close.
7. **No `bin` field** — registration uses explicit `node dist/index.js` command. `bin` would require shebang + compiled JS only.
